## Field definitions

Fields are those of `UxCounts` in `tests/unit/ux-counts.test.ts`, computed in `countFixture`. Every
count is per fixture. The TOTAL line sums them, except the two description-length fields (see
"Description lengths in the TOTAL line").

- `fixture`: the file path, or `stress:<id>` for a built stress fixture. `fixtures` (TOTAL only) is
  the number of fixtures.
- `plans`, `addOns`: the number of plans and of add-ons of the view model.
- `rows`: comparison rows over all groups. `groups`: comparison groups.
- `rowsAboveProposedCapInGroups`: per group, the rows above 8, summed. 8 is a proposed threshold for
  the narrow layout (`COMPARISON_ROWS_PROPOSED_CAP`), not a renderer value.
- `groupsAboveProposedCap`: groups with more than 8 rows.
- `rowsAboveRendererCapInGroups`: per group, the rows above 30, summed. 30 is the real cap,
  `group.rows.slice(0, 30)` in `src/element/renderers.ts` (`RENDERER_ROWS_CAP`).
- `addOnOnlyRows`: rows for which `isAddOnOnlyRow` is true: every plan cell is empty and some add-on
  provides the row.
- `addOnOnlyRowsMisleading`: add-on-only rows whose marker is misleading **at the default selected
  plan**: no add-on that provides the row can be bought on that plan. It counts **rows** at one plan,
  not cells, so 137 is not a cell count.
- `addOnMarkerCellsMisleading`: table-layout cells rendered with the add-on marker
  (`pr-value--addon`) in a plan column where no providing add-on can be bought (`markerCells`).
  Cells, all plans, from the real render of `renderComparison`.
- `planDescriptionsMissing`, `addOnDescriptionsMissing`: items whose description is undefined or
  blank after trim (`isBlank`).
- `planDescriptionsFiller`, `addOnDescriptionsFiller`: items whose description equals the name.
  `isFiller` trims and lowercases both sides, the same rule as `rowDescription` in
  `src/element/renderers.ts`.
- The plan and add-on description counts read `plan.description` and `plan.name`, and
  `addOn.description` and `addOn.name`. They are kept as before; row descriptions have their own
  fields below.
- `addOnsNotAvailableForSelectedPlan`: add-ons with a non-empty `availableFor` that does not include
  the selected plan (`availableForPlan`).

Part (a), units of numeric cells. A numeric cell is a comparison row cell whose resolved value is a
finite number, in a row that has a unit; this is how `renderValue` in `src/element/renderers.ts`
reaches `formatUnit`. Formatting uses the real `formatUnit` with the view model's
`presentation.unitLabels`, in locale `en` unless stated. Each distinct unit of a fixture is
classified once, by `classifyUnit`, from the documented rules and not from the code path of
`formatUnit`. The first matching reason wins, in this order: unit-label override, slash, upper case,
digit or whitespace, trailing `s`, other characters (not only `a` to `z`), singular candidate.

- `numericUnitCells`: numeric cells in rows that have a unit.
- `singularCandidateCells`: those cells whose unit is a singular candidate: it matches `^[a-z]+$`,
  does not end in `s`, and has no override.
- `singularCandidateCellsChangedAt0`, `...At1`, `...At5`: candidate cells whose unit `formatUnit`
  changes for a count of 0, 1 and 5. Expected: all, none, all.
- `singularCandidateCellsUnchangedAtActualCount`: candidate cells whose unit stays as written for
  the cell's own value, when that value is not 1 or -1. Expected 0.
- `unitsDistinct`: distinct units of numeric cells, counted once per fixture (a unit used in two
  fixtures counts twice in the TOTAL line).
- `unitsSingularCandidate`, `unitsLeftSlash`, `unitsLeftUpper`, `unitsLeftDigitOrSpace`,
  `unitsLeftTrailingS`, `unitsLeftOtherChars`, `unitsOverridden`: the distinct units by reason.
  These seven partition `unitsDistinct`.
- `unitsLeftNonEnglish`: singular candidates that stay as written when formatted under locale `es`
  for a count of 5 (no `es` or `*` override). It is a second view of the candidates, not part of the
  partition.

Part (b), add-on markers.

- `mixedRowsProvidedByAddOn`: rows that are not add-on-only, have at least one empty and one filled
  plan cell, and are provided by some add-on. Their empty cells render `—` although an add-on fills
  the row.
- `addOnMarkerCellsTotal`: all table-layout cells rendered with the add-on marker, whether or not
  misleading.

Part (c), row descriptions. A row is missing (blank), filler (the description equals the row name
after trim and lowercase, the rule of `rowDescription` in `src/element/renderers.ts`, so the
renderer does not show it) or described.

- `rowDescriptionsMissing`, `rowDescriptionsFiller`, `rowDescriptionsDescribed`: they add up to
  `rows`.
- `rowDescriptionLengthMax`, `rowDescriptionLengthMedian`: the trimmed length of the description of
  the described rows only. The median is the lower median and is 0 for an empty set.
