Export `selectionToSearchParams` and `selectionFromSearchParams` from the core, free of the DOM, with the option types `SelectionToSearchParamsOptions` and `SelectionFromSearchParamsOptions`. The writer turns a selection into `[key, value]` string pairs and the reader takes any `Iterable<[string, string]>`, such as a `URLSearchParams`, and returns the `applySelectionInput` result. The URL format: `plan=<id>`, `billing=<id>`, one `addon=<id>` or `addon=<id>:<quantity>` per selected add-on (the quantity is written when it is not 1 or the id contains `:`), and one `var.<path>=<json>` per variable, where text that is not JSON is read as a string. An optional `prefix` applies to every key, so several renderers can share one URL; the reader's `current` option keeps its plan or billing period when the URL names an unknown one. URL input is untrusted: the reader ignores `__proto__`, `prototype` and `constructor` path segments, array indexes that are not canonical or not below the array length, digit segments under anything but an array, `__proto__` keys inside JSON values, values longer than 2048 characters, paths of more than 8 segments, values nested deeper than 8 levels and every entry after the first 100; unknown ids are reported through the existing `PR_SELECTION_UNKNOWN_*` warnings, cut to 64 characters. Value types are not checked against the pricing, so a host still re-prices and revalidates the selection on its server.
